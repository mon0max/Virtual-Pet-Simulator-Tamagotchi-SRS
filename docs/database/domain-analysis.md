# Анализ предметной области

Источники: техническое задание в Wiki; задачи #2 (создание питомца), #3 (кормление и поение), #4 (игра), #5 (сон), #21 (предметы и инвентарь), #24 (история действий). Инвентарь включён в модель по согласованию в рамках лабораторной №4.

| Сущность | Назначение | Основные данные |
| --- | --- | --- |
| Users | Владелец питомцев | идентификатор, имя пользователя, дата создания |
| Pets | Питомец и его текущее состояние | владелец, имя, окрас, сытость, утоление жажды, счастье, энергия |
| Action_Types | Справочник действий ухода | идентификатор, уникальный код и название |
| Actions | История действий над питомцем | питомец, вид действия, время |
| Items | Каталог предметов из #21 | идентификатор, уникальный код, название, тип |
| Pet_Items | Инвентарь питомца | питомец, предмет, количество |

Связи: Users 1:N Pets; Pets 1:N Actions; Action_Types 1:N Actions; Pets M:N Items через Pet_Items. Каждая дочерняя запись имеет обязательную ссылку на родителя; у родителя допустимо отсутствие дочерних записей.

Границы модели: проектирование SQLite-схемы хранения и истории ухода, включая согласованный инвентарь. Существующий браузерный прототип хранит данные в localStorage. Подключение SQLite, авторизация, транзакции покупки и интерфейс магазина в лабораторной №4 не реализуются. Поля каталога и инвентаря моделируют хранение предметов; цены, баланс и механика экономики остаются задачей #21. Модель допускает несколько питомцев у владельца; это возможность хранения, а не добавленная функция интерфейса.
